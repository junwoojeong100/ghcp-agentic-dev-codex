요청된 기록과 실제 변경 파일을 대조해 AC-1~AC-8 충족 여부, 보안·상태 전이·UI 렌더링 위험을 코드
근거와 기록된 테스트 근거로 분리해 검토하겠습니다.

계획 승인은 simulated-rehearsal로 명시되어 사람 승인으로 볼 수 없습니다. 이제 기록된 검증 결과와
실제 diff·구현을 독립적으로 대조해 테스트 기록과 코드 판독 근거를 분리하겠습니다.

정적 검토상 핵심 통제는 대체로 구현되어 있으나, 서비스 역할 경계와 테스트가 실제 요구를 정확히
고정하는지 추가 확인이 필요합니다. 변경 파일의 정확한 줄 범위와 fixture/HTTP 어댑터 맥락을 읽어 최종
지적 사항을 확정하겠습니다.

3. 지적 사항

높음 — 감사에서 입력 변조 차단 시도가 누락됨
파일: src/refunds.mjs:63-72, README.md:24-27, test/refunds.test.mjs:24-28,144-176

허용 필드 검사가 actor와 환불 조회보다 먼저 실행되어 { actorId: "cs-kim", amount: 1 }처럼 유효한
actor·환불에 대한 금액 덮어쓰기 시도도 400만 반환하고 events에는 기록하지 않습니다. 따라서 “차단한
시도를 화면에서 확인”한다는 요구와 AC-5의 “유효한 actor·환불에 대한 성공·차단 업무 동작”을 충족하지
못하며, README의 모든 차단 업무 동작 기록 주장도 실제보다 넓습니다. 기존 테스트는 400 응답만
확인하고 감사 이벤트 생성 여부는 검증하지 않습니다.

제안: actor와 refund를 식별할 수 있는 요청은 먼저 안전하게 조회한 뒤, 허용되지 않은 필드 검사를
blocked(...) 경로로 처리하십시오. 금액 덮어쓰기와 임의 필드 요청이 400이면서 outcome: "blocked"
이벤트를 남기는 테스트도 추가해야 합니다.

4. 남은 위험

 - 역할 선택과 actor ID는 클라이언트가 지정하는 모의 신원이며 실제 인증·권한 부여가
아닙니다(public/index.html:21-22; README.md:45-47).
 - 상태와 감사 이력은 프로세스 메모리에만 있어 재시작·reset으로 사라집니다. 변조 방지 영구 감사
저장소가 아닙니다.
 - UI의 안전한 텍스트 렌더링은 코드 판독으로 확인했지만, 제공된 프로젝트 테스트에는 브라우저 DOM/XSS
전용 검증이 없습니다.
 - 기록된 테스트 통과와 해시 값은 제공 자료의 주장입니다. 이번 검토에서 명령을 재실행하거나 해시를
독립 검증하지 않았습니다.

5. 사람이 결정할 사항

감사 누락을 수정하고 금액 변조 차단 이벤트 테스트를 보강할지 사람이 결정해야 합니다. 그 전까지 최종
상태는 Hold / human review pending이며, 이 검토는 GitHub Copilot code review 제품이나 PR 승인·병합
승인이 아닙니다.
