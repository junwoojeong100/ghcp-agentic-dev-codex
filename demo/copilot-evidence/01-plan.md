# 환불 승인 통제 구현 계획

## 문제와 접근

현재 `src/refunds.mjs`의 `process`는 금액과 역할을 검사하지 않고 요청된 환불을 즉시 `completed`로 바꾼다. 정책은 `enforced: false`로 반환되고 이벤트 이력은 매 조회마다 빈 배열로 만들어져 요청·차단·결정의 추적도 불가능하다. 화면에는 승인·반려 동작이 연결되어 있지 않다.

확인된 범위와 완료 기준에 따라 1,000,000원 이상은 요청 후 승인 대기시키고 요청자와 다른 승인자만 결정하게 한다. 소액 즉시 처리 흐름을 유지하며 성공·차단 업무 동작을 감사 이력 및 화면에 남긴다. 역할 선택은 데모용으로 유지하고 인증·금전 이동·영구 저장은 구현하지 않는다.

## 작업 항목

1. 환불 서비스에 금액 임계값 정책, 요청/대기/완료/반려 상태 전이, 역할 권한 및 오류 응답을 구현한다.
2. 성공·차단 동작을 식별 가능한 actor, 금액, 사유와 함께 순차 감사 이벤트로 기록하고 reset·요약·인스턴스 격리를 보장한다.
3. 기존 화면 구조와 접근성 ID를 유지하면서 역할별 환불 요청·승인·반려·차단 확인, 대기 요약, HTTP 상태 알림 및 감사 타임라인을 연결한다.
4. 경계 금액·권한·오류·감사·화면 수용 기준을 테스트하고 README를 갱신한다. 지정된 단위·인수 테스트, `git diff --check`와 diff 검토를 수행한다.

## 검토 기준과 유의점

- 수정 범위: `src/refunds.mjs`, `public/index.html`, `public/app.mjs`, `public/styles.css`, `test/refunds.test.mjs`, `README.md`만.
- 1,000,000원 미만은 즉시 완료(HTTP 200), 이상은 승인 대기(HTTP 202); 금액은 서버의 seed 데이터를 기준으로 한다.
- 처리 시작은 support 역할만 가능하다. 고액 요청자는 자기 승인할 수 없고, 별도 approver만 승인·반려할 수 있다. 차단 시도와 terminal 상태 충돌은 구분해 기록한다.
- 반려 이유 검증, 알 수 없는 필드 및 금액 변경 거부, actor·환불 존재 확인과 의미 있는 감사 사유를 포함한다.
- 구현 완료나 테스트 성공은 실제 인증·영구 감사·결제의 준비를 의미하지 않는다. 출시 판단은 HOLD다.
